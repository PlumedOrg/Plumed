# Plumed architecture

Where things live and how the main features work. Rules and processes (branching, releases, conventions) are in [AGENTS.FORK.md](../AGENTS.FORK.md), which includes this file. Keep it in sync with the code: a change to a feature described here updates its paragraph in the same commit.

## Overview

Plumed is a Tauri app:

- `src-tauri/`: Rust backend (audio, speech model, post-processing, paste, settings, PhoneMic client).
- `src/`: React + TypeScript frontend (Tailwind CSS, shadcn/ui, lucide-react).
- `PhoneMic_server/`: the relay (Rust, axum) and the phone page, see its README and `protocol_details.md`.

Main flow of a dictation:

1. The shortcut starts the recording (push-to-talk or toggle), the overlay shows it.
2. On release the audio goes through the pipeline (`src-tauri/src/audio/pipeline.rs`): transcription with beam search and phrase boosting, sound-alike pass, then the Corrections steps (see below).
3. The text is typed directly, or pasted (clipboard saved, text set, Ctrl+V simulated, clipboard restored).

Backend modules (`src-tauri/src/`), one directory per feature: `audio/` (recording, pipeline), `engine/` (Parakeet runtime, beam search, boosting, confusion pass), `model/` (catalog, download, store), `medical/` (medical lists, data updates), `grammar/`, `formatting_rules/`, `dictionary/`, `history/`, `clipboard/`, `shortcuts/` (per OS backends), `overlay/` (overlay window, tray), `settings/`, `remote_mic/` (PhoneMic), `telemetry/`, `stats/` (local usage stats on the home page), `utils/` (HTTP client, platform helpers, user text checks, Wayland injection), `commands/` (Tauri commands), `cli/`, plus `app_update.rs` (app updates). `lib.rs` builds the app (plugins, state, commands).

Frontend (`src/`): `components/` shared UI primitives, `features/<feature>/` one folder per page or feature, `i18n/locales/` translations.

Translations: i18next with English sentences as keys (punctuation matters, changing the sentence changes the key). Use `t('Check for updates')`, run `pnpm i18n:extract`, fill `src/i18n/locales/fr.json`. Interpolation: `{{variable}}` in both key and value. Keys stay flat (no nesting).

## Speech engine

- Regex cache (`formatting_rules/formatter.rs`, `REGEX_CACHE_CAPACITY` 4096) is for user rules (incl. 45 seeded dictation rules). The ~45,000 drug/term rules bypass it: `src-tauri/src/medical/` indexes them by anchor word and compiles lazily.
- Benchmarks: ParakeetWeb's `benchmark_datasets/french_medical/`, clips padded with 0.25 s silence like the app (unpadded clips drift into English). Harness: ignored test `phrase_boost::model::tests::bench_transcribe` (`PLUMED_BEAM_WIDTH`, `PLUMED_CONFUSION`). Upstream's boost fed the ~77k phrases makes WER worse (its rank gate suits few words); the trie fixes it.
- Decoder (`src-tauri/src/engine/beam.rs`, port of ParakeetWeb's `parakeet.js`): MAES width 5, 2 expansion steps, beta 2, gamma 2.3, prefix alpha 1; duplicates merge by log-sum-exp, per-frame pruning by raw score, final pick length normalized. Step score = true token log-prob + boost bonus (boosted minus raw logit) + duration log-prob; ranking by boosted logits. Each hypothesis carries its own decoder, dictionary boost and trie state. `ParakeetInferenceParams::beam_width` (default 5); preview uses `ParakeetInferenceParams::greedy()`; width 1 runs the original greedy decoders. Divergence guard compares against unboosted greedy, then reruns unboosted at the requested width. Joint calls batched (`Parakeet::decode_steps`), beam 5 costs ~1.1x to 1.9x greedy. v2 int8: WER 2.97% greedy, 2.82% beam 5.
- Boost tuning for v2: weight 0.5, commitment 0.5, min-p 0.01 (the v1 tuning 1.5/0/0.01 made v2 worse than no boost). Benchmark regenerated from the v2 corpus with ParakeetWeb's `gen-medical-val-sets.mjs` (seed 1234, 400 clips, none in v2 training). v2 label conventions differ from v1 ("1" for "un/une", "postopératoire", "80000").
- Confusion second pass (`src-tauri/src/engine/confusion.rs`): after the beam, a word listed in UltiMed's `confusion_groups.jsonl` is re-scored with the previous word on its encoder frames (best TDT alignment per candidate, unboosted), replaced only when a candidate scores higher. Option "Resolve sound-alike medical words", final transcriptions only, default margin 0 (fixed 6, broke none of 233 cases).

## Speech models

Speech models: not bundled. The first startup wizard step (`src/features/onboarding/startup-wizard/steps/model-step.tsx`, `ModelChooser` with `hideDownload`) downloads the chosen variant in the background into `<app data>/models/` (survives updates). Same component (`model-chooser/`) is Settings > Model. No manual check button: SHA-256 checked during download, full check by `manager::check_after_load_failure` on load failure.
- Catalog (`src-tauri/src/model/catalog.rs`): UltiMed v1 Ultra int8 (default, 668 MB) and w4a8 (402 MB) at revision `ce5160b` first. v2 variants (int8, w4a8, revision `675b4b8`) are `experimental: true`, listed last with "(EXPERIMENTAL)", never recommended, and open a warning dialog (`src/features/model/experimental-model-dialog/`): v2 does much worse than v1 in real dictation despite better benchmark WER. v1 and v2 share vocab/config/preprocessor; medical data applies to every model. Redux w2a8 is "bientôt disponible" and unpickable (WER 5.04%, TODO in the catalog). Sizes and SHA-256 compiled in.
- Recommendation (`catalog::recommended`, `model/memory.rs`): under 8 GiB RAM the lightest variant, else the first (rationale in `LOW_MEMORY`). Returned as `recommended` by `get_model_status`, preselected and marked "Recommandé". Every variant installs under the engine's file names (`encoder-model.int8.onnx`, `decoder_joint-model.int8.onnx`, `nemo128.onnx`, `vocab.txt`, `config.json`). Repos and revisions in `PhoneMic_server/protocol/src/models.rs` (`MODEL_REPOS`), shared with the relay; a test checks the catalog only uses them.
- Store (`store.rs`): folder per variant and revision (`ultra-int8-675b4b8d7ee9/`), `.partial` files, `model.json` marker written last, `active.json`. Launch does a cheap check; on load failure a full hash check drops a damaged model (dialog instead of crash). Other revisions removed after a successful download.
- Download (`download.rs`, `manager.rs`): Hugging Face (redirects only to its https hosts), then relay `https://models.plumed.fr/models/<repo>/<path>?revision=<commit>` (`PhoneMic_server/models/`). Range resume, 3 attempts per source with backoff, cancel, progress, disk space check, size + SHA-256, atomic rename, one at a time. Errors: typed `DownloadError`, French via `downloadErrorMessage`.
- `PLUMED_MODEL_RELAY_URL` (optional, build time, `option_env!` in `download.rs`, default `https://models.plumed.fr`): workflows pass the **repository variable** `${{ vars.PLUMED_MODEL_RELAY_URL }}`.
- No model when recording: main window, "Aucun modèle téléchargé" toast, wizard on its model step (`model-missing` event). The model step is always first (`getDueSteps`). Telemetry `model` field = active variant id (`dev` or `none` otherwise).
- Development: debug builds fall back to `resources/parakeet-tdt-0.6b-v3-int8/`; run `bash scripts/fetch-ultimed-model.sh` once (also for `engine::beam`'s ignored test). Release bundles list resources explicitly in `tauri.conf.json` so that folder never ships. CI doesn't fetch the model, except the Intel macOS smoke test (`--models-dir`).
- Adding a model: publish on Hugging Face with the same layout, add repo + revision to `MODEL_REPOS`, add the variant with sizes and hashes to `catalog.rs`, keep old revisions in `MODEL_REPOS` while released apps use them, redeploy the relay, bump `MODEL_ID` if the family changes.

## Medical data updates

Medical data updates (rules, confusion groups, phrase list updated without an app release). Code: `src-tauri/src/medical/data_set/` (the one place knowing bundled vs downloaded: manifest checks, on-disk sets, fallback), `src-tauri/src/medical/data_update.rs`, `src-tauri/src/commands/medical_data.rs`, frontend `src/features/medical-data/` and `src/features/onboarding/` (`startup-wizard/steps/medical-data-step.tsx`, `medical-data-prompt/`). Manifest format and storage: "Online updates" in `src-tauri/medical-data/SOURCE.md`.
- Consent: no network call before the first launch question is answered; sets `medical_data_update_check` and `medical_data_update_asked` (never exported). "Yes" checks from the next start.
- Flow: once per launch, fetch `manifest.json` + signature from the `medical-data` release (plain GET, UA `Plumed`, no id or cookie). A valid, newer, not skipped set opens a dialog (Not now / Skip this version / Download); nothing downloads without the click. Lists switch live. User edits are never touched; edits of vanished rules are kept and marked. UI: Online tab (`src/features/settings/system/online-settings/`, the one place showing `MedicalDataSettings`).
- Review: a collapsed "Review the changes" section of the dialog (`update-changes-review.tsx`, command `preview_medical_data_update`) downloads the set into staging without installing it (kept in `Pending.staged`, reused by Download) and lists per file the lines added and removed against the data in use (`data_set::diff`, set comparison, 50 sample lines per side).
- Failed check: error taken once per launch (`take_medical_data_check_failure`), toast linking to the release page (system browser) plus manual install hint.
- Manual install: user picks `manifest.json`, `manifest.json.minisig` and data files (multi-select; others ignored). Same code as online: `data_set::checked_manifest` (signature, allowlist, sizes, hashes, model, `min_app_version`, newer), `data_set::StagedFile`, `install_in`. Refusals are typed `SetError`, explained in French by `medicalDataSetErrorMessage`.
- Failsafe: also refused when >5% of rules don't parse, phrase list or confusion groups have under half the bundled entries, or rules rewrite >8 more sentences than bundled on `medical-data/canary/correct_sentences.txt`. All checks rerun at each launch; failure falls back to bundled data, never a partial set.
- Key: dedicated minisign key (not the updater key), `minisign -G -p plumed-rules.pub -s ~/.minisign/plumed-rules.key`, secret key out of the repo (maintainer keeps both in `~/.minisign/`). The base64 line of the `.pub` is the **repository secret** `PLUMED_RULES_PUBKEY`, passed by every `tauri build` workflow, read with `option_env!` in `src-tauri/src/medical/data_set/mod.rs`. Unset or empty: feature inert.
- Publishing: `scripts/publish-medical-data.sh <version> "<notes>"` (signs with `PLUMED_RULES_KEY`, default `~/.minisign/plumed-rules.key`; uploads to the `medical-data` prerelease created with `--latest=false` so it never hides the app's `latest.json`). Bump `BUNDLED_VERSION` in `data_set/mod.rs` when bundled files change, `MODEL_ID` when the model family changes (old sets then refused).

## Usage statistics

Usage statistics (opt-in, `src-tauri/src/telemetry/`), build-time via `option_env!`:
- `PLUMED_TELEMETRY_WEBSITE_ID`: Umami website id, passed by every `tauri build` workflow from the **repository secret** of the same name. Unset or empty: telemetry inert (no dialog, no setting, nothing sent). Sends wait a random delay up to 15 min.
- `PLUMED_TELEMETRY_URL` (optional, default `https://metrics.plumed.fr/api/send`): deliberately not passed by workflows (empty would override the default); local test builds only.
- Server (VPS): Caddy proxies only `POST metrics.plumed.fr/api/send` to Umami (`localhost:3823`), else 404. Own log `/var/log/caddy/metrics-plumed.log` (logger `metrics_plumed` via `log_name`, kept out of `access.log`, full IPs, mode 0600, no rolling) pruned to 24 h by root timer `caddy-prune-metrics-log.timer` (`/usr/local/sbin/caddy-prune-metrics-log.py`); the privacy policy states this. Root timer `umami-purge-plumed.timer` runs `/usr/local/sbin/umami-purge-plumed.sh` daily, deleting Plumed rows older than 25 months from every table with `website_id` (`RETENTION='0 seconds'` to test).

## PhoneMic

Phone as microphone through the relay (`PhoneMic_server/`, HTTPS long-poll, end-to-end encrypted). Desktop client in `src-tauri/src/remote_mic/` (`client.rs` relay HTTP, `crypto.rs`, `protocol.rs` pairing and frames, `session.rs` lobby, page check and recording queue, `qr.rs`), frontend in `src/features/extensions/remote-mic/`. Wire format shared with the relay by the `plumed_relay_protocol` crate (`PhoneMic_server/protocol/src/lib.rs`); the phone page (`PhoneMic_server/server/static/`) mirrors it in JS, both pinned by `test-vectors.json`. Full spec and threat model: `PhoneMic_server/protocol_details.md`; deployment and release routine: `PhoneMic_server/README.md`. Keep `protocol_details.md` in sync with any wire change.
- Protocol version (`PROTOCOL_VERSION`, 5.0.0, served at `/api/version` and mixed into `HKDF_SALT`): the desktop refuses a relay with any other version, no backward compatibility on purpose (`check_version_answer`, `ClientError::ProtocolMismatch`). A newer relay (`relay_is_newer`) shows `APP_OUTDATED` with an "update Plumed" offer (`remote-mic-session.tsx` via `useAppUpdate`) instead of looking suspicious. Bump it and regenerate the crypto test vectors on any wire change.
- Pairing (since 4.0.0): the QR link `<origin>/p/<page version>/#<room>.<phone secret>.<desktop public key>.<pairing secret>` carries a pairing secret; the phone's `hello` includes a proof derived from it (`crypto.rs` `derive`), so no code comparison. The QR only holds the phone's room secret (no desktop inbox access). A bound phone is dropped after `BOUND_LIFETIME` (12 h, `protocol.rs`).
- Delivery (5.0.0): end-to-end `ACK` every `ACK_EVERY` (16) in-order packets, the phone resends what is unacknowledged, the desktop signals gaps once (`protocol.rs`, phone `app.js`).
- Phone page: versioned apart from the protocol (`PAGE_VERSION` in `PhoneMic_server/protocol/src/page.rs`, served at `page_path`, older pages archived in `server/pages/<version>/`, emptied on a protocol bump), each Plumed links to and checks its own page version (`ClientError::PageMissing`: `PAGE_TOO_OLD` asks to update Plumed, `PAGE_TOO_NEW` blames the relay).
- Page check: once per session, after a random 2 to 9 s delay (`page_check_delay`), `RelayClient::check_page` fetches every page file with phone headers and compares it byte for byte with the copy embedded in `page.rs`; a mismatch (`PageTampered`) stops PhoneMic, other failures only log.
- Phone session resume (`PhoneMic_server/server/static/store.js`): the bound session (room, secret, inbox, non-extractable AES keys, sequence numbers) is kept in IndexedDB for 12 h (`LIFETIME_MS`, matches `BOUND_LIFETIME`) so a reload needs no new scan; deleted on any terminal error.

## App updates

Tauri updater (`src-tauri/src/app_update.rs`, commands in `src-tauri/src/commands/app_update.rs`: `set_app_update_channel`, `check_app_update`, `install_app_update`); frontend `src/features/update-checker/` (sidebar `update-checker.tsx`, `hooks/use-app-update.ts` = `useAppUpdate` shared with PhoneMic's update offer, `app-update-channel-select/`), setting in the Online tab (`app-update-settings/`), startup wizard step `update-channel-step.tsx`.
- Channel (`UpdateChannel`, setting `app_update_channel`, sent in usage statistics): `stable` (default) reads the latest release's `latest.json`; `beta` reads the 10 newest releases and takes the newest carrying `latest.json`, prerelease or not; `disabled` checks only when the user asks (`check(manual)`). Only newer semver versions install, so switching back to stable never downgrades.
- Sources: GitHub first, then the relay (`relay_base`, paths in `PhoneMic_server/protocol/src/releases.rs`), installer URL rewritten to the relay too. The installer signature is checked against the key in `tauri.conf.json`, so a relay cannot forge an update. UA `Plumed`, 20 s timeout.

## Features

- Settings > Corrections (`src/features/corrections/`): Explanation tab (`corrections-explanation.tsx`, before/after cards in code order) then 1 Medical vocabulary, 2 Sound-alike words, 3 Personal dictionary, 4 Clean-up and standardization (hesitations, short text correction, spaces, numbers), 5 Residual errors, 6 Formatting (user rules, seeded from `dictation_rules.csv`), 7 Grammar, 8 Text templates. Single source: `PIPELINE_STEPS`, `CLEAN_UP_OPTIONS`, `pipelineStepTitle` in `corrections.helpers.ts`, tab names in `CORRECTIONS_TAB_LABELS` (also import/export categories). Short text correction and pre-installed formatting are step 4 options that run after steps 5 and 6 (`CLEAN_UP_OPTIONS.runsAfter`), shown as "applied after step N". Step numbers use `StepBadge` (`step-badge/`), in tabs via the `prefix` slot of `components/tabs.tsx` (sideways scroll: `components/use-sideways-scroll.ts`); history lists the options as sub-lines (`changesInStepOrder`). When order or lists in `src-tauri/src/audio/pipeline.rs`, `src-tauri/src/formatting_rules/formatter.rs`, `src-tauri/src/medical/`, `src-tauri/src/grammar/` or `src-tauri/src/engine/` change, update `PIPELINE_STEPS`, `history::PipelineStep` (`src-tauri/src/history/steps.rs`), the tab and French strings. URL hash selects the tab; old `rules`/`custom-rules` hashes open Formatting. Fold state of "Your formatting rules" is localStorage `plumed:user-rules-collapsed`, never exported.
- Text templates (`src-tauri/src/medical/text_templates.rs`, tab `src/features/corrections/text-templates/`): spoken trigger replaced by a longer, possibly multi-line text. Bundled example in `src-tauri/medical-data/text-templates/templates.jsonl`, OFF by default (`OverlayEntry::OFF_BY_DEFAULT`, `ListOverlay::initial` until `text_templates.json` is saved; "Back to the original list" saves it, `get_initial_text_template_overlay`). Expansion uses `formatting_rules::apply_custom_rule` smart mode, runs last (step 8) after grammar in `audio::pipeline::apply_formatting_rules`, recorded as `PipelineStep::Templates`; not in the `apply_formatting` preview nor the history highlighter. Editing a bundled template (`saveTemplateEdit`) disables its key and adds a user copy; static list refreshed by `text_templates::activate`. Validation via `user_text.rs` (below). Export category and telemetry flag `text_templates`, native format JSONL.
- History step details: optional `steps` (`step_id`, `text_after`) filled via `StepTrace` by `audio/pipeline.rs` and `formatting_rules::apply_formatting_traced` (keyboard in `finalize_chunked_session`, PhoneMic chunks via `history::steps::join_parts`; CLI and previews use `StepTrace::off()`). Boosting and sound-alike share one "Recognition" step. Same storage rules as history (memory, disk only with `persist_history`, 5 entries). Word diff in frontend (`src/features/home/history/history-steps/`, no dependency).
- Settings page (`/settings`, `src/features/settings/system/system.tsx`): tabs General, Shortcuts (`src/features/settings/shortcuts/`), Online, Advanced, Model, Overlay, Import / export (`src/features/settings/import-export/`). `/settings/import-export`, `/settings/system`, `/settings/shortcuts` redirect; hash selects the tab. Online (`online-settings/`) holds everything touching the network, with an intro listing each connection (update check, model download, medical data, usage statistics, PhoneMic relay): keep it true when network features change. Default paste method is Direct, except Wayland (Ctrl+V) (`default_paste_method` in `src-tauri/src/settings/types.rs`).
- Medical list overlays (kept across data updates; entries a newer set lacks stay saved and shown): `medical_rules.json` (`medical/drug_rules.rs`), `medical_phrases.json`, `medical_confusion_groups.json` (`medical/list_overlay.rs`), all held by `medical/store.rs`; `engine_lists.rs` applies them when arming and re-arms on change. Each tab has Import, Export (JSONL for rules and groups, one phrase per line, `.murmure` for formatting rules, `.txt` for the dictionary), "Back to the original list"; importing a bundled list stores its diff; invalid files save nothing.
- Grammar step 7 (`src-tauri/src/grammar/`): last step for keyboard and PhoneMic, in `audio/pipeline.rs` `apply_formatting_rules` after formatting. Option `built_in.grammar` (on, in `formatting_rules.json`, telemetry `grammar`). Per line: spell checker's unknown words, the 18 masks of `grammar-data/grammar_rules.json` (port of UltiMed's `mask.py`; Python `re` syntax translated by `mask::python_to_fancy`), Grammalecte on the masked line, errors mapped back, then only fixes from enabled rules with exactly one suggestion and type outside `skip_types` (never typography), applied right to left. 8 allowlisted rules on by default; the tab (`src/features/corrections/grammar-tab/`) lists other measured families (aggregate stats from `eval/al_final/*.tsv`), off by default. Overlay `ListOverlay<String>` in `grammar_rules.json` (`GRAMMAR_OVERLAY`); export one id per line (`ListFile::Grammar`); `grammar_rules` is a `.murmure` and `plumed import` category.
- Grammalecte runtime: 2.3.0 (GPL v3+, AGPL-compatible). No Python or PyInstaller sidecar (antivirus false positives): the JS build from the Firefox extension runs in Rust via QuickJS (`rquickjs`), no webview, CSP stays strict. `scripts/fetch-grammalecte.sh` downloads it (SHA-256 pinned) and extracts files listed in `grammar-data/grammalecte-files.txt` into `resources/grammalecte/` with `grammar-data/LICENSE-grammalecte.txt`; every workflow runs it and `cargo test` needs it. `grammar/host.js` is our glue (data loading, Python default options, which differ from JS defaults). One thread (`grammar/worker.rs`) loads it (~1 s); a dictation waits at most 20 s, else the step is skipped. UTF-16 offsets converted to code points (`engine.rs`). Parity: ignored test `grammar::engine_tests::parity_with_the_python_reference` on private lines in `PLUMED_GRAMMAR_PARITY` (never commit that file). Credits and source offer: `fork-credits.tsx`, README, `grammar-data/SOURCE.md`.
- Settings export (`.murmure`): `medical/changes.rs` adds `medical_phrases`, `medical_confusion_groups`, `medical_rules`, `grammar_rules`, `text_templates` (overlays and edits only). App (`src/features/settings/import-export/medical-changes/`, `get_medical_changes`, `import_medical_changes`) and `plumed import` (`cli/import.rs`, `ExportedCategories.medical` flattened) both use `medical::changes::import`: replace or merge by key, validate every list (`set_overlay`, `set_edits`) before saving any. The CLI copies from `SystemSettings`, which has no network setting, so imports can never enable a network feature.
- Import preview (`src/features/settings/import-export/medical-changes-review/medical-changes-review.tsx`, wired by `buildRenderers` in `import-export.renderers.tsx`): before applying, the import dialog lists under each medical category every entry of the file, as "Added or changed" or "Turned off" (`changeLines`), so a shared file cannot slip in a rule or template unseen. Read-only: each list imports as a whole.
- Overlay window capability (`src-tauri/build.rs`, `src-tauri/capabilities/overlay.json`): `build.rs` reads `generate_handler![...]` in `src/lib.rs`, registers it as the app manifest (`allow-<command>` each) and rewrites the committed `src-tauri/permissions/main-commands.toml`, granted to main in `capabilities/default.json`. New commands are main-only until added by hand to `overlay.json`. Overlay has `core:event:allow-listen`, `allow-unlisten`, `get_all_settings`, `cancel_recording`, `set_overlay_input_region`, `hide_overlay_if_idle`, `ack_result_panel_shown`, `consume_pending_result`, `copy_result_text`; extend it when `src/overlay/` calls something new. `generate_handler!` entries must stay plain identifiers, one per line.
- Local transcription API (`src-tauri/src/local_api/`, off by default): OpenAI-compatible `POST /v1/audio/transcriptions` (multipart `file`, 16-bit PCM WAV only, `response_format` `json` or `text`) and `GET /v1/models`, axum on `127.0.0.1` only. Middleware order in `server.rs`: foreign `Host` gives 403, any `Origin` header gives 403 (blocks browser pages), then the bearer key (constant-time compare) or 401. One transcription at a time (`busy` mutex), in `spawn_blocking`, via `audio::pipeline::transcribe_samples_chunked` (same pipeline as `plumed transcribe`, no history, no local stats). Settings `local_api_enabled`, `local_api_port` (4800), `local_api_token` (`plumed-` plus 48 hex chars from `ring`), never exported; new key names so Murmure's old `api_enabled` stays ignored. In-app server started or stopped by `local_api::apply_settings` (at startup and from the commands in `commands/local_api.rs`); a failed start turns the setting back off. Headless `plumed serve [--port N]` (`serve_headless`) refuses while the setting is off, reads the key at startup, preloads the model, stops on Ctrl-C; skips single-instance like `transcribe`. UI: `src/features/settings/system/local-api-settings/`. Telemetry: `Source::Api` counts into `Counters.api`, sent as `api_*` keys, plus flag `local_api`.
- PhoneMic late paste (`remote_mic/session.rs`): a recording still queued after `MAX_QUEUE_AGE` (30 s) is dropped, and a transcript ready more than `MAX_PASTE_DELAY` (20 s) after `END` reached the desktop (`Queued::at`) is not pasted; it stays in history, clipboard untouched, toast via `remote-mic-late-transcript` / `RemoteMicLateListener`.
- Temporary recordings (`src-tauri/src/audio/helpers.rs`, `ensure_recordings_dir`): `plumed_recordings` in `$XDG_RUNTIME_DIR` on Linux if set and writable, else the app cache dir; never the shared temp dir. Checked: owned by us, not a symlink, 0700.
- CSP (`app.security.csp` in `tauri.conf.json`, main and overlay): `'self'`, `ipc:`/`http://ipc.localhost`, `data:` images (PhoneMic QR from `remote_mic/qr.rs`), `'unsafe-inline'` styles (inline `<style>`, react-toastify and UI libs). `dangerousDisableAssetCspModification: ["style-src"]` prevents a style nonce that would void `'unsafe-inline'`; scripts keep nonces, no `unsafe-eval`. The frontend makes no network call itself (everything via Rust commands): keep it so or extend `connect-src`.
- `block_cli_import` (`AppSettings`, Settings > Advanced) defaults to true: `plumed import` is refused until turned off. Only settings files without the key get the default.
- GitHub Actions pinned by full commit hash with tag comment (`uses: actions/checkout@<sha> # v4`); `.github/dependabot.yml` bumps them weekly. Resolve new tags with `gh api repos/<owner>/<repo>/git/ref/tags/<tag>` and, for annotated tags, `gh api repos/<owner>/<repo>/git/tags/<sha>`.
- `/dev/uinput` udev rule (`packaging/linux/60-plumed-uinput.rules`, the only copy: imported `?raw` by `wayland-listener.tsx` for `UINPUT_FIX_COMMAND`, checked by a test in `utils/wayland_inject.rs`): `TAG+="uaccess"`, `MODE="0660"`, no `GROUP`. Not shipped in deb/rpm/Arch packages (no `files` entry, no udevadm in `postinst`/`postrm`/`.install`); the user installs it in `/etc/udev/rules.d/` via the command the app shows. Old packages' `/usr/lib/udev/rules.d/60-plumed-uinput.rules` (`GROUP="input"`) is removed by package managers on upgrade.
- User and imported entry checks (`src-tauri/src/utils/user_text.rs`, the one place): `has_unsafe_chars` (control and bidi chars; medical replacements, confusion forms, dictionary words, template triggers), `has_unsafe_chars_besides_lines` (allows `\n` and tab; formatting replacements, template text), `check_entry_count` (`MAX_USER_ENTRIES` = 50,000 user-added entries per list; disabled bundled keys and bundled edits not counted). Confusion groups: max 20 candidates (`MAX_CANDIDATES`, `medical/list_overlay.rs`). Enforced at save (`formatting_rules::save`, `dictionary::store::save`, `ListOverlay::validate`, `medical::validate_edits`) so every import path goes through them.
- Startup wizard (`src/features/onboarding/startup-wizard/`, in `layout.tsx`): one non-dismissable dialog, one step per unanswered question (model, PhoneMic only without microphone, usage statistics, medical data check, update channel), "Retour" and "n / N" dots. `getDueSteps` (`startup-prompts.helpers.ts`) decides from backend flags (`telemetry_asked`, `medical_data_question_due`, `remote_mic_prompt_due`, `app_update_channel_asked`). New questions are new steps, not popups. `medical-data-prompt/` waits for a launch without the wizard. Afterwards, users who never opened the tutorial go to `/tutorial` (`tutorial_opened`).
- Usage statistics "Plus tard" (`src-tauri/src/telemetry/reask.rs`): re-asked after 7 days, 10 dictations and 3 launches; third ask offers "Ne plus jamais demander". Local counters in `telemetry_ask.json` (never sent), deleted on a definitive answer. Commands `get_telemetry_question`, `postpone_telemetry_question`.
- Tutorial (`src/features/tutorial/`): commands in `tutorial.data.ts` must stay real default rules of `src-tauri/medical-data/regex-fixes/dictation_rules.csv`; its only template example is the bundled "examen clinique normal" with a "Turn it on" button (`tutorial-template.tsx`). Progress in localStorage `plumed:tutorial-used` (`tutorial-progress.ts`, never exported). "J'ai terminé le tutoriel" sets `tutorial_completed` (never exported, sent as a yes/no telemetry flag, see PRIVACY_POLICY.md).
